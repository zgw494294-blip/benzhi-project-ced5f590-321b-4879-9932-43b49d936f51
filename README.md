# 古树复壮作业放行台

古树复壮作业放行台是面向巡护员、方案编制人员和古树保护复核人员的单流程 Web 应用。系统从古树作业建档开始，依次完成四类现场调查、风险形成、逐项处置、方案送审、退回整改与复验、版本冻结，最终签发不可变的开工放行凭据。未覆盖风险、未完成调查或未闭环问题均无法越级放行。

## 核心能力

- 作业档案保存古树编号、位置、保护等级、责任人和计划作业窗口，并以 `DRAFT` 状态开始。
- 树冠、主干、根区、周边环境调查均保存结构化事实和文本证据；草拟期可用带理由的取代记录更正事实，原记录永久保留。快照预检会集中阻断缺项、多条有效记录和重复证据。
- 调查事实可自动生成风险，也可补充人工风险；风险按严重度与紧迫性形成稳定排序的三级工作清单，编制人员可在送审前原子批量复核紧迫性。已被措施引用的风险不能删除。
- 每个风险必须在同一修订中具备处置措施、禁止事项、验收标准和唯一实施顺序，送审后该修订被锁定。
- 复核人员可对当前修订措施批量登记逐项通过或退回；退回必须记录具体问题，工作台按待提交证据、待复验、复验未通过和已关闭整理整改待办。
- 冻结清单以稳定顺序规范化全部事实并计算 SHA-256 摘要；冻结内容、归档清单和放行凭据不可通过业务接口修改。
- SQLite 事务同时写入聚合、只追加审计事件、幂等响应、冻结归档和凭据；`expectedVersion` 提供乐观并发控制，凭据序号单调递增。
- 浏览器工作台位于 `GET /workspace`，凭据可按作业或完整递增编号精确核验，并独立显示内容完整性、作业窗口状态与是否可开工。

## 构建

需要 Go 1.22 或更高版本。项目使用纯 Go SQLite 驱动，无需额外安装 SQLite 动态库。

```text
go build ./...
```

## 运行

默认监听高位回环地址 `127.0.0.1:19081`，数据保存在当前目录的 `restoration.db`：

```text
go run ./cmd/server -addr=127.0.0.1:19081
```

启动后访问 `http://127.0.0.1:19081/workspace`。可用 `-db` 指定 SQLite 文件。未显式传入 `-addr` 时，如果 `PORT` 是 `1024` 到 `65535` 的合法端口号，服务将监听 `127.0.0.1:<PORT>`。服务拒绝非回环监听地址，不会默认绑定 `0.0.0.0`。

## 测试与自检

运行全部单元和集成测试：

```text
go test ./...
```

运行有界自检。该命令会在实际配置地址启动 HTTP 服务，使用内存 SQLite 经由同源 JSON 路由完成建档、四类调查、风险生成、措施覆盖、逐项通过、冻结、批准和凭据核验，随后自行退出：

```text
go run ./cmd/server -addr=127.0.0.1:19081 -selfcheck
```

## 目录结构

- `cmd/server`：监听配置、服务装配、优雅关闭和完整流程自检。
- `internal/domain`：聚合、实体、状态机以及冻结和放行不变量。
- `internal/application`：角色校验、用例编排、并发与幂等元数据、可读进度视图。
- `internal/store`：SQLite 迁移、事务、乐观并发、只追加归档和完整性检查。
- `internal/audit`：规范化冻结摘要、审计连续性检查和凭据完整性核验。
- `internal/web`：同源 HTTP 路由、输入限制、错误映射以及原生 HTML、CSS、JavaScript 工作台。

## 正常业务流程

1. 以巡护员角色创建档案，逐项登记树冠、主干、根区和周边环境调查及证据，再确认调查完整。
2. 以方案编制人员角色生成风险，为每个风险保存相同修订号下的完整措施，并提交复核。
3. 以保护复核人员角色逐项通过或退回。退回项由编制人员补充整改证据，再由复核人员记录复验结论。
4. 所有当前修订措施均通过且退回问题全部闭环后，复核人员冻结版本并批准签发开工凭据。
5. 在凭据卡片按作业或编号执行重新核验，系统同时检查只追加归档、冻结规范化内容、当前事实、冻结版本、结构版本和 SHA-256 摘要；只有完整且当前处于计划作业窗口才显示可开工。
